# ADR-0002：Stage A容量实测后的双分支模型选择

- 状态：已决定
- 日期：2026-08-29
- 范围：《斗破苍穹》v4固定语料、本机Apple M4 16GB、正式预训练前选型
- 取代：ADR-0001中“参数固定为810万且不再放大”的容量判断；其SFT治理和检索增强决策继续有效

## 新证据

Stage A在测试集封存条件下完成两轮可归因实验。BPE 1000/2000/3000使用同一4M模型训练500步，3000 merges取得最低验证BPC 5.8747。随后固定3000 merges，将420万、836万、1488万模型各从随机权重训练1000步；验证BPC分别为5.4969、5.3820和5.3239。

1488万相对836万改善约1.08%，但耗时从22.5分钟增加到38.2分钟，吞吐从3035降到1785 Token/s。三个模型都只暴露409.6万训练Token；1488万仅得到0.275 Token/参数，所以本轮是短程筛选，不是充分训练。

## 决策

1. 最大质量分支采用3000 merges、Embedding 320、10层、8头、FFN 1280、Context 512，共14,880,745参数。
2. 高频本机迭代分支保留3000 merges、Embedding 256、8层、8头、FFN 1024，共8,362,025参数。
3. 下一阶段先正式训练最大质量分支，并以验证BPC和生成Harness共同早停；不使用测试集选步数。
4. 旧2000 merges/810万参数checkpoint与新模型不兼容，正式预训练必须从随机权重开始，之后重新SFT。
5. 章节级事实继续采用检索增强；扩大参数不能替代证据检索、SFT数据治理或偏好数据质量。

## 边界

1488万是当前测试范围内的质量冠军，不是已证明的绝对上限。因为最大候选仍优于较小模型且曲线尚未反弹，若项目必须严格寻找容量拐点，应追加约2400万参数的短程对照；在追加实验前，不宣称“斗破苍穹只能支撑1488万参数”。

短程样本仍有重复、语法混乱和情节拼接。BPC只决定正式训练候选，最终模型必须同时通过验证BPC、重复率、Distinct-2/3、EOS、固定续写、人物一致性和人工语义抽查。

## 后果

- 最大质量分支比原810万路线更慢，并需要全新的预训练和SFT成本。
- 836万仍是本机调数据、调Harness和验证训练代码的默认配置。
- RLHF/PPO不进入当前步骤；只有SFT模型达到基本行为门槛且已有可靠偏好对时，才考虑DPO类偏好优化。
