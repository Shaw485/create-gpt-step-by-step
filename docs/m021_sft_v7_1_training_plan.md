## 1. 结论先行

GPT 在结构上始终只预测下一个 Token。小说续写与问题回答不是两种模型能力，而是同一个生成目标在不同数据格式下形成的两种行为：

```text
纯小说预训练：前文 → 下一段小说
问答 SFT：用户问题 + 助手角色 → 答案
垂直 RAG：用户问题 + 检索证据 + 助手角色 → 有证据的答案
```

因此，单本《斗破苍穹》原著能够提供小说语言、人物共现、情节局部关联和叙事风格；它不会自动提供稳定的问答格式、自然停止、开放世界知识或精确全书统计。M021 按以下职责边界执行：

| 能力 | 主要责任方 | M021 目标 |
|---|---|---|
| 中文小说表达、局部续写、高频人物补全 | 纯预训练基座 | 保留，不因 SFT 明显退化 |
| 核心人物身份、别名、直接关系、核心设定 | 参数内 SFT | 能直接、简短、正确作答 |
| 给定片段后的抽取、解释、改写、判断 | SFT + 当前上下文 | 能从证据推出答案，不抄整段原文 |
| 首次出现、精确章节、全书次数、长尾多跳关系 | 检索与实体索引 | 先检索，再由模型组织答案 |
| EOS、长度、格式、多轮承接、诚实边界 | SFT | 学会自然交互和停止 |
| 天气、绿巨人、数学、通用百科 | 不属于本项目正向能力 | 简短说明能力边界，不注入伪知识 |

M021 的成功定义不是“训练出通用 ChatGPT”，而是得到一个可验收的垂直助手：核心事实可直接回答，复杂事实可基于检索回答，小说表达能力保留，领域外问题不猜测。

## 2. 本阶段明确不做什么

| 决策 | 当前结论 | 重新讨论的前提 |
|---|---|---|
| 扩大参数量 | **不做**，继续使用 14,880,745 参数、BPE 7,465、Context 512 | v7.1 数据与训练配方已通过，指标进入平台期，并新增至少约一倍合法同域唯一 Token |

模型结构、Tokenizer 和 Context 均不改变，因此不需要从随机权重重新预训练。当前优化对象是监督数据、训练配方、选择指标与检索边界。

## 5. Now：64 条 Canary 容量与管线探针

### 5.1 目的

Canary 不追求覆盖整本小说，只回答一个最重要的问题：**14.9M 模型和当前 assistant-only 训练管线，能否学会少量、直接、经过核验的小说问答？**

如果模型连 64 条对齐监督都无法拟合并泛化到简单改写，问题优先位于数据格式、标签、EOS、优化器或模型容量，而不是“还缺 10,000 条数据”。

### 5.2 数据构成

- 选择 8 个已核验 catalog fact ID，每个 fact 制作 8 条自然训练问法，共 64 条；其中父子关系和药尘/药老关系存在命题重叠，约对应 7 个独立命题簇，因此评估必须同时看总体与逐 fact 结果。
- 八个 fact ID 覆盖：萧炎身份、萧战身份、药尘身份、药老/药尘别名、药老/萧炎师徒关系、焚决、异火炼药作用、云岚宗身份；每个 fact 都包含裸问、自然改写、关系正反问、纠错和正误判断。
- 回答保持事实所需的最短自然长度，正式编码实测为 5–16 个监督 BPE Token；不为凑长度填充内容，也不使用“原文写道”“文本中出现”“可以先记录问题”等统一包装。
- 每条事实绑定已审核事实 ID、证据行号元数据和父数据清单 SHA；Canary 不复制证据正文，后续正式 v7.1 再为证据型任务冻结逐条证据 SHA。
- 训练集之外冻结 16 条完全未见自然改写（每个事实 2 条）作为 Dev/Selection。它们不参与梯度，但参与 teacher-loss 与 provisional checkpoint 选择，因此不是盲测，也不与 Public/Sealed 混用。
- Canary 只使用 train 与独立 canary diagnostic；不读取 `public_diagnostic` 或 `sealed_test` 正文。

### 5.3 训练检查

训练必须从 Step 5750 全新初始化，先执行以下顺序：

1. 对 1 个 batch 人工核验 Token、role 边界、assistant-only mask、EOS 和目标错位。
2. 用 2 条样本运行单 batch 过拟合，确认 Loss 显著下降且能生成目标答案。
3. 扩到 64 条；每 25 步记录 train Loss、梯度范数、学习率、EOS 和固定输出。
4. 最多运行 500 步；达到全部退出门即提前停止，不因 Loss 继续下降而追加步数。
5. 用两个固定随机种子复核，排除一次随机好运。

### 5.4 Canary 硬门

| 指标 | 通过门槛 |
|---|---:|
| 64 条训练问题规范化完整答案匹配 | ≥95% |
| 16 条 Dev/Selection 未见问法规范化完整答案匹配 | ≥75% |
| 每个 fact 的训练完整匹配 | ≥7/8 |
| 每个 fact 的未见改写完整匹配 | ≥1/2 |
| 四个核心固定问题 | 4/4 |
| 16 条未见改写出现 EOS | ≥15/16 |
| 达到生成上限 | 0 |
| 严重机械重复 | 0 |
| 自指关系错误，例如“药尘是药尘的老师” | 0 |
| 空回答或已知事实误拒 | 0 |
| 预训练固定 16 题非空 | 16/16 |
| 固定窗口 BPC 相对退化 | ≤5% |

只有所有硬门同时通过，才进入 A0。Canary 的规范化完整答案匹配是为这组固定短答案设计的严格容量探针；正式 v7.1 必须改用结构化命题规则与独立语义审核，不能把关键词命中或 exact match 冒充通用语义正确率。失败时按以下顺序排查：assistant-only mask、输入目标错位、角色/EOS Token、生成模板、学习率/梯度、容量。不得直接增加样本或训练 Step 掩盖故障。

### 6.1 数据硬规则

- 先冻结至少 64 个高价值原子事实，全部人工核验，再扩展自然问法。
- 每个核心事实至少覆盖：裸问题、两种自然改写、纠错题和多轮追问；训练与评测问法模板不得重复。
- 核心事实回答以 12–40 Token 为主，先给结论；证据型回答以 24–96 Token 为主。
- 任一答案前 8 字占 train 的比例不得超过 1%；通用完整答案最多重复 3 次。
- 非引用任务中，答案与证据超过 50% 字符覆盖的样本不得超过 10%。
- 自指关系、错误实体、错误别名、无法由证据推出的结论、元包装和占位回答必须为 0。
- 已知核心事实误拒必须为 0；未知问题只说明具体缺少什么，不附带无关小说片段。
- 三联校准必须保留：核心已知直接答、无证据长尾问题索证、给出有效证据后恢复作答。
- 数学、通用百科正向答案、项目学习问答保持为 0。
- 目标不是保住较长回答数量；目标是让每个 assistant Token 都提供事实、推理、表达或停止信号。

## 7. A/B/C 训练配方消融

先在 A0 上并行比较三种配方，每种先运行 500 步：

| 配方 | Peak LR | 辅助原始预训练 Loss 回放 | 用途 |
|---|---:|---:|---|
| A | `1e-5` | 0 | 检验降低 M020 学习率后的纯 SFT |
| B | `5e-6` | 0 | 检验更保守更新能否减少遗忘 |
| C | `1e-5` | 平均权重 `0.1` | 检验训练期原始小说 Token 回放能否保留语言能力 |

A0 中“原生小说续写保持回放”是 SFT 格式的续写任务；C 中的“辅助预训练回放”是额外 next-token objective，两者不得混写。

共同配置：

- Micro Batch：2。
- Gradient Accumulation：4。
- 有效 Batch：8。
- 最大序列长度：512；使用实际长度分桶，避免无意义 Padding 主导计算。
- Warmup：50 步。
- 学习率：Warmup 后 cosine 衰减，最低 `1e-6`。
- AdamW：`betas=(0.9, 0.95)`。
- Weight Decay：`0.01`；Norm 与 Bias 不衰减。
- Dropout：`0.1`。
- Gradient Clip：`1.0`。
- 每 125 步保存 checkpoint、运行固定题和 Canary 回归。
- 每 250 步运行 Public 自动评估与 M019 Retention。
- 固定随机种子、数据顺序清单和训练签名；记录实际样本池抽取覆盖率。

三种配方到 500 步后，只保留满足 Stop/Go 门的方案。最优方案运行到 1000 步；Top 2 使用第二个随机种子复核。选择顺序固定为：硬门是否通过 → 核心事实 → 证据支持 → 重复/EOS → Retention → Loss，同分时 Loss 才能作为 tie-break。

## 8. Stop/Go 规则

### 8.1 立即停止

出现任一条件即停止当前 run：

- 固定窗口 BPC 相对 Step 5750 退化达到 10%。
- 预训练固定续写不是 16/16 非空。
- 出现 NaN/Inf、梯度爆炸、checkpoint 血缘或数据 SHA 不一致。
- 连续两个评估节点只有 Val Loss 下降，Public 通过门数量、固定题正确率和重复率均未改善。
- 固定核心题正确率下降，或严重重复连续两个节点恶化。
- 训练器、编码器或日志触及 public/sealed 正文。

### 8.2 500 步 Go 门

所有条件同时满足才允许延长：

- Public 自动通过门数量超过 M020 最好值 `5/15`。
- 固定 16 题基本通过数超过 M020 最好值 `1/16`，且核心 4 题为 4/4。
- 严重机械重复显著低于 M020 约 40% 的 Public 水平。
- EOS ≥90%，空回答为 0，截断 ≤10%。
- BPC 相对退化 ≤8%，固定小说续写 16/16 非空。
- 自指关系错误和已知事实误拒均为 0。

### 8.3 阶段 Go 门

A0→A4 每次扩展时，上一阶段核心指标不得回落超过 2 个百分点，Retention 硬门不得恶化。若新增任务提高其自身指标却破坏核心问答，则回退数据权重或训练配方，而不是继续堆 Step。

## 9. RAG 并行建设

RAG 与 Canary/A0 并行，不等待 SFT 全部完成。它不是用于掩盖基础问答失败，而是承担参数模型不适合精确记忆的任务。

### 9.1 冻结索引

- 按正式章节建立稳定 `chapter_id`、标题、正文行号、章节 SHA。
- 建立人物、别名、势力、地点、功法、异火和事件实体索引。
- 建立实体逐章出现次数、首次出现和共现表；统计口径必须记录是否包含标题、别名归一和引用片段。
- 第一版检索使用字符/BPE 关键词 + BM25；需要时再加入稠密检索，不能先用复杂模型掩盖索引错误。
- 产品索引可覆盖已授权的完整小说，但必须在任何 sealed 评估前冻结 SHA；不得把 sealed 问题或参考答案写入索引。
- 每次返回 1–3 个短片段，为回答至少保留 128 Token；Context 总长保持 512。

### 9.2 三层验收

| 层级 | 指标 | 中间门槛 | 发布门槛 |
|---|---|---:|---:|
| 检索器 | Recall@k | ≥95% | ≥95% |
| Gold evidence 生成器 | 语义正确 | ≥80% | ≥90% |
| Gold evidence 生成器 | 证据支持率 | ≥90% | ≥95% |
| 端到端 RAG | 正确率 | ≥80% | ≥85% |
| 端到端 RAG | 抗干扰 | ≥85% | ≥90% |
| 无答案检测 | 正确停答 | ≥90% | ≥95% |

只有检索器本身通过后，端到端错误才归因给生成器；报告必须分开记录 retrieval miss、generator miss、unsupported claim 和 routing miss。

### 10.1 Public 自动门

最终候选必须同时满足：

| 维度 | 发布硬门 |
|---|---:|
| 固定 16 题基本通过 | ≥15/16 |
| 核心 4 题 | 4/4 |

所有门都是硬门，不能以平均分抵消事实错误。Val Loss 只监控优化过程，不能单独选模。

### 10.2 独立真人审核

- Public 自动门全部通过后，才启动 600 条 Public 双人盲审。
- 两名审核者独立标注事实正确、问题相关、证据支持、表达自然、边界诚实和严重重复；不展示 checkpoint 名称。
- 分歧样本由第三人裁决；AI 辅助审核必须单独标注，不能冒充真人。
- 真人门未通过时，候选退回数据或配方阶段；任何修改都要重新运行完整 Public，不能只修失败题。

### 10.3 一次性 Sealed

只有一个 checkpoint 可以进入 sealed。进入前必须冻结：模型 SHA、Tokenizer SHA、索引 SHA、生成参数、路由规则、评测代码 SHA 和验收阈值。

sealed 状态机固定为：

```text
frozen_unspent → claimed/in_progress → spent
```

- 读取正文前先原子写入 `claimed/in_progress`；即使进程崩溃也视为 `spent`，不得重跑或调参。
- 评测只输出聚合指标与不可逆 case id，不输出题面、参考答案、证据正文或模型完整回答。
- 当前 M021 开发、Canary、A0–A4、Public 与日志测试均不得读取 sealed 正文。
- Sealed 失败即记录失败并开启新的里程碑；不得用结果回调 M021。

## 16. Canary 实际结果与更新后的训练决策

### 16.1 已执行实验

所有实验都从纯预训练 Step 5750 独立初始化，没有从 M020 或其他 SFT 权重续训：

| 实验 | Peak LR | Replay Weight | Step | Train/Dev 严格答案 | 固定窗口 BPC 退化 | 小说续写非空 | 决策 |
|---|---:|---:|---:|---:|---:|---:|---|
| 高 LR 容量探针 | 1e-4 | 0 | 375 | 100% / 100% | +43.64% | 9/16 | 只证明容量，淘汰 |
| 低 LR 无回放 | 1e-5 | 0 | 200 | 35.94% / 12.50% | +3.38% | 12/16 | 问答不足，淘汰 |
| 联合回放 | 1e-5 | 0.50 | 400 | 81.25% / 62.50% | +1.89% | 15/16 | 问答门失败 |
| 联合回放 | 1e-5 | 0.25 | 400 | 87.50% / 68.75% | +2.33% | 15/16 | 当前最优诊断节点，非候选 |
| 联合回放 | 1e-5 | 0.10 | 400 | 87.50% / 68.75% | +3.05% | 13/16 | 被 0.25 支配，淘汰 |

联合回放的优化目标为：

```text
total_loss = assistant_only_sft_loss
           + replay_weight × pretrain_next_token_loss
```

Replay 只读取正式预训练 Train Token。每个 400 步实验消费 400 个 replay batch、1,600 个窗口和 204,800 个目标 Token；预训练 validation/test 与 SFT public/sealed 的优化消费均为 0。

### 16.2 评分修正而非追溯改门

`0.25` 组的 13 条严格失败经非盲命题复核后，8 条是语义等价，5 条是真错误。命题正确率为 Train 61/64（95.31%）、Dev/Selection 14/16（87.50%），逐 fact 最低值分别为 7/8 与 1/2。

原严格 exact 结果保持不变；命题复核只证明正式 A0 需要结构化实体、关系、方向和任务相关性规则。它不能替代 public、独立真人或 sealed 验收。详细证据见 [M021 里程碑](../reports/milestones/021_sft_v7_1_canary/README.md)。

### 16.3 A0 更新方案

下一阶段不直接训练旧 v7 的 10,000 条分布，而是先重构 3,920 条 A0 Train：

- 核心事实、别名、关系与纠错：1,920 条；
- 领域边界、索证与给证据后恢复：960 条；
- SFT 格式原生小说续写保持：1,040 条。

训练配方以 `replay_weight=0.25` 为中心，只比较 `0.20/0.25/0.30`，固定 Peak LR `1e-5`、Seed、数据和评估协议。每 125 步先过结构化问答、关系、EOS 与重复门；通过后才运行固定窗口 BPC 和 16 条小说续写。BPC 退化达到 10%、续写不是 16/16 非空或连续两个节点只改善 Loss 而不改善行为时立即停止。

只有 A0 同一 checkpoint 同时通过结构化问答、EOS/重复、BPC ≤5% 退化和 16/16 小说续写，才允许进入 A1 单证据任务。Public 在配方冻结后使用，sealed 仍只允许单一最终候选一次性验收。
