# M003a：SFT 20步安全试跑

## 目的

本阶段只验证 SFT 训练闭环，不追求最终问答效果。模型从 `sft_stage1_init_pre_sft.pt` 开始，用40条训练数据更新参数，用5条验证数据选择最佳 checkpoint；5条固定测试数据不进入训练脚本。

## Loss 范围

每条序列仍为 `<BOS><USER>问题<ASSISTANT>回答<EOS>`。问题和补齐位置的标签为 `-100`，交叉熵只计算回答字符与 `<EOS>`。变长序列在批次末尾补 `<PAD>`；因果注意力使末尾补齐不会影响之前的回答位置，同时补齐标签为 `-100`，不会进入 Loss。

## 试跑配置

- Step：20
- Batch Size：4
- Learning Rate：`1e-4`
- Weight Decay：`0.01`
- 梯度裁剪：`1.0`
- 每5步完整评估40条训练和5条验证记录
- CPU训练，随机种子42

## Loss 结果

| Step | 训练 Loss | 验证 Loss |
|---:|---:|---:|
| 0 | 4.4718 | 4.4909 |
| 5 | 3.5110 | 4.0600 |
| 10 | 2.9547 | 3.8431 |
| 15 | 2.4593 | 3.6525 |
| 20 | 1.9940 | 3.4976 |

训练 Loss 下降约55.4%，验证 Loss 下降约22.1%，说明回答监督、反向传播和参数更新均已生效。训练与验证之间的差距已经扩大到约1.50，表明40条训练数据非常容易被记忆；后续不能只看训练 Loss，也不能盲目训练几千步。

第20步监控结果中，训练问题“萧炎的父亲是谁？”生成了“萧炎的实力。”并主动输出 `<EOS>`；验证问题仍生成无关文本。这说明模型开始学到回答长度和停止行为，但20步尚不足以形成可靠问答能力。

最佳验证 Loss 在第20步取得，最新 checkpoint 与最佳 checkpoint 都已保存。训练脚本没有读取 `test_records`，报告中的 `test_records_consumed` 为0。

## 日志与诊断

数据、训练步骤、验证与 checkpoint 分别写入 `logs/sft_train_data.log`、`logs/sft_train_step.log`、`logs/sft_train_validation.log`、`logs/sft_train_checkpoint.log`。四类日志可以用对应的 `SFT_*_LOG_LEVEL` 独立调整或关闭，文件最大1 MB并保留3个轮转备份。
