# M017：1488万模型正式 SFT 数据准入审查

## 结论

总体结论是 **Needs revision（需要重构，不能直接进入正式 SFT）**。

当前最新候选 `v5.2.2 core routing` 有4516条，结构完整、BPE 3000全部可编码、没有精确重复问句，实体拒答修复方向也有效；但“文件名叫training-ready”不等于内容已达到正式训练准入。全量复算发现2340条仍标记为`pending`，995条含“原问题是/当前证据片段/现只做局部证据核验”等元话术，1299条依靠固定风格前缀扩写问法，且缺少多轮、长上下文和长回答。

更严重的是，自动规则在全量数据中找到了2条确定的章节顺序错误和17条残缺标点答案。此前独立AI决定文件曾把其中一条错误测试记录`v4_b104ab5fa11b82a768f4`标成`approved`：问题问第167章的下一章，答案却说第162章。这个反例证明，过去的600条批量AI审核不能继续作为“语义已验收”的充分证据。

因此下一步不是立刻把4516条换BPE后开训，而是先生成新的冻结版SFT数据：隔离确定错误、重写机械包装、压缩重复模板、补齐缺失能力，再重新划分验证和封存测试集。

## 规模是否足够

当前3479条训练记录只有68789个BPE监督Token（答案加EOS），平均答案18.46 Token；1836条答案不超过16 Token，没有一条答案达到128 Token。完整序列平均48.88 Token、最大127 Token，完全没有使用Context 512的中长上下文。这个规模足够做20步流程冒烟，也足够修一个窄行为（例如“萧炎是谁”不拒答），但不足以支撑1488万参数模型稳定完成小说问答、自然聊天、证据阅读和多样长度回答。

SFT没有像预训练那样可靠的“每个参数必须对应多少Token”公式，质量和覆盖比纯数量更重要。结合当前模型容量、单本小说知识范围和本机训练成本，推荐正式冻结版为：

- **合理范围：8000至12000条高质量唯一记录。**
- **中心方案：10000条**，其中train 8000、val 800、公开诊断600、最终封存test 600。
- train答案监督量目标为 **30万至50万BPE Token**；完整输入序列约80万至150万Token。
- 平均答案从18 Token提高到35至50 Token，同时保留短答、中答和少量长答，不用大量空洞长文凑Token。
- 不建议直接扩到数万或十万条模板数据；对1488万小模型和单本小说来说，重复合成会比数据不足更快伤害效果。

## 当前维度是否充分

表面上有21个`task_family`，高层比例也不算失衡：小说事实/证据类56.5%，自然聊天16.1%，项目与学习14.4%，指令7.7%，能力边界4.2%，概念解释1.1%。但任务名字多不等于能力充分。

当前明显缺少：

1. **多轮对话：0条。** 模型没有被教过如何承接“他是谁”“继续说”“我指的是药老”等上下文。
2. **中长上下文：0条达到128 Token问题，0条序列超过256 Token。** Context 512没有在SFT中被利用。
3. **中长回答：0条达到128 Token。** 模型主要学的是十几Token短答，无法靠增加生成上限自动学会完整回答。
4. **自然的摘要、改写、解释和续写。** v5.1为清理污染把整类任务删除了，应该用干净正例恢复，而不是继续缺失。
5. **广覆盖实体知识。** v5.2重点卡只有15个已知实体和8组关系，能修核心人物，但不足以覆盖全书人物、宗门、地点、功法、丹药、异火与别名。
6. **真正未见事实的封存评估。** 现有隐藏20题已经用于best/latest比较，现有test又存在同事实与去前缀同题重合，不能继续承担最终盲测。
7. **回答风格和长度的分布。** 需要短答、解释、分点、引用证据和有限长答，而不是全部“一句话”。
8. **对话纠错与恢复。** 用户否定模型、补充条件、改口或要求重答的多轮训练几乎为空。

不缺数学题；数学继续排除是符合项目目标的决定。现阶段也不需要RLHF或DPO来掩盖SFT数据问题，偏好训练必须等SFT行为门通过后再做。

## 新冻结版准入门槛

1. P0风险为0；章节顺序、证据结论和成对标点机械复核全部通过。
2. `pending`为0；AI审核身份如实记录，关键事实和最终test另做独立抽样。
3. “原问题是/现只做局部证据核验/正确，证据支持”等训练元话术为0。
4. 去风格前缀后的重复问题不跨最终test；同证据事实只允许进入“已见事实改写集”，不得进入“未见事实集”。
5. 一般任务的完全相同答案最多重复5次；拒答类占比控制在5%以内。
6. BPE 3000全部可编码，序列不超过512；长度桶、实体、章节、任务配额都有机器报告。
7. 至少1000条多轮记录、1000条128至384 Token的证据上下文、15%左右中长回答。
8. 新建未见实体/未见事实/多轮/长上下文四类封存测试；checkpoint只用val和公开诊断选择，最终test只评估一次。

## 执行顺序

1. 先隔离19条P0记录，并将243条verification wrapper整类退出正式候选。
2. 对2340条教师数据按风险重审：优先1364条任务变换，再审核其余976条；不再继承旧AI“approved”作为充分结论。
3. 把995条元证据包装改成自然问题，压缩1299条前缀模板和1600条重复答案。
4. 建立全书实体/别名/关系/章节证据卡，补齐小说事实和RAG式上下文问答。
5. 补多轮、长上下文、中长回答和自然语言任务，扩到8000至12000条。
6. 按语义事实而不是记录ID重新切分，冻结四轨评估集。
7. 通过全部数据门后，用BPE 3000编码；先从M016 Step 5750做20步安全试跑，再决定正式SFT步数。

## 局限与置信度

自动审查能证明结构、重复、长度、Token兼容、明显错章和格式破损，但不能证明每个小说答案都语义正确。风险队列中的记录不一定全部错误；没有被规则命中的记录也不等于已批准。因此本报告对“当前不可直接正式训练”的判断置信度高，对“最终每条应该保留还是改写”仍需下一阶段逐条证据审查。
