# M014：已知实体路由修复与可恢复 SFT Harness

## 结论

本轮已经修复“小说萧炎是谁/小说药尘是谁却回答资料不足”的核心问题。v5.2.2 最新模型在公开人物题达到 4/5，在未进入训练数据的隐藏实体题达到 19/20；已知实体 9/10、虚构实体 10/10、EOS 20/20。

当前仍不是成熟聊天模型：无数学公开综合诊断只有 10/30，未达到 18/30 门槛；“丹王是谁”仍可能不回答古河，精确指令、能力边界和部分事实问答也需要继续提升。

## 根因与修复

M013 的 3629 条训练记录中，已知人物正例稀疏，而未知/澄清样本过强。旧训练还会随机重复样本，续训没有恢复 optimizer、随机数和 sampler 状态，名义上的 5000 步并不等于完整覆盖数据。

本轮执行了以下修复：

- 删除 207 条不自然的“如果用户只说请介绍……”元澄清、254 条无证据的裸未知拒答和 59 条稀疏旧人物样本。
- 新增 360 条实体修复：核心实体 120、扩展实体 120、关系 40、纠错 40、有语料前提的未知 40。
- 核心实体为萧炎、药尘、药老、异火、萧战，每个在 train 有 20 种自然问法；其余 10 个实体每个 8 种。
- 训练采样分成通用回放 45%、核心实体 35%、扩展实体/关系 15%、有证据未知 5%。每个池内部先无放回遍历，再开始下一轮。
- checkpoint 现在保存和恢复模型、optimizer、全局随机状态、采样器队列和覆盖率；验证 Loss 使用完整 495 条 val，而非少量随机 batch。
- 公开分类评分收紧，不能再把“萧炎是丹王人物”之类只命中“人物”的错误答案判为通过。

## 日志与独立调试

训练日志位于 `runs/sft_v5_2_2_core_probe1000/logs/`，按 `data`、`sft`、`validation`、`checkpoint`、`orchestrator` 分文件；数据构建和隐藏评估日志位于本目录 `logs/`。每条结构化 JSONL 日志包含时间、级别、模块和 `run_id`，不记录问答正文、密码、Token、密钥或完整授权头。

模块级别可在 `configure_module_loggers` 的映射中分别设为 `DEBUG`、`INFO`、`WARNING` 或 `OFF`。正式配置默认启用轮转，单文件 10 MiB，保留 5 份。排查示例：

```bash
rg '"level": "ERROR"' runs/sft_v5_2_2_core_probe1000/logs/
rg '"module": "cloud.validation"' runs/sft_v5_2_2_core_probe1000/logs/
```

本轮验证了成功路径、错误 checkpoint 路径、Tokenizer 词表不兼容、无 NaN/Inf、checkpoint 保存和 26 项定向测试。失败会记录操作和堆栈后重新抛出，不会静默吞掉异常。
