# M002：字符级 SFT 数据集 v1

## 这一阶段做了什么

本阶段没有训练模型，而是把原始小说知识整理为可监督训练的“问题—回答”样本。种子集包含 16 条问答，其中训练集 12 条、验证集 4 条；每条记录都保存了原文证据、原文行号和独立知识主题。

## 为什么先做小数据集

SFT 的关键不是先堆数量，而是先验证格式、标签和 Loss 计算范围。若格式错误，即使扩展到一万条也只会更快地训练出错误行为。M002 先把完整流程跑通，M003 再扩充数据并开始微调。

## 一条样本怎样进入模型

```text
<BOS><USER>问题<ASSISTANT>回答<EOS>
```

这五个标记都作为完整 Token 加到原字符词表末尾。基础词表为 4478，扩展后为 4483。

输入与标签错开一位。问题部分的标签被设为 `-100`，交叉熵会忽略它们；只有回答字符和 `<EOS>` 参与 Loss。这样模型学习的是“看到用户问题后应该回答什么”，而不是浪费主要训练目标去背诵问题。

## 数据质量约束

1. `evidence` 必须原样出现在 `source_line` 指定的授权语料行中。
2. 问题和回答不得包含基础字符词表以外的字符。
3. `id` 与问题不能重复。
4. 同一 `topic` 不能同时出现在训练集和验证集，防止改写问题造成验证泄漏。
5. 验证集仅用于观察泛化，不参与参数更新。

## 文件

- `data/sft/sft_seed_v1.jsonl`：人类可读的问答、证据和切分。
- `data/sft/sft_seed_v1_tensors.pt`：模型可读取的变长 Token 与标签。
- `sft_data_report.json`：数量、词表、Loss 标签和哈希报告。
- `prepare_sft_data.py`：验证并生成张量的可复现脚本。
- `logs/sft_data.log`、`logs/sft_validation.log`、`logs/sft_output.log`：分模块诊断日志。

## 如何独立调试

三个日志类别互相独立，可分别用 `SFT_DATA_LOG_LEVEL`、`SFT_VALIDATION_LOG_LEVEL` 和 `SFT_OUTPUT_LOG_LEVEL` 设置为 `DEBUG`、`INFO`、`WARNING`、`ERROR` 或 `OFF`。例如只查看证据校验，可将数据和输出日志设为 `OFF`，将验证日志设为 `DEBUG`。`SFT_CONSOLE_LOG=0` 可关闭终端日志，但轮转文件仍保留；每个日志文件最大 1 MB，保留 3 个备份，日志不记录问答全文或任何凭证。

重新生成和复现错误的命令是：

```bash
./.venv/bin/python prepare_sft_data.py
```

## 当前限制

16 条记录只够验证 SFT 机制，不能让模型获得成熟问答能力。下一阶段需要先扩充并人工复核训练问答，再从 M001 最佳预训练 checkpoint 初始化 SFT；特殊 Token 对应的新增参数需要单独初始化，原有 4478 个 Token 的参数保持继承。
